> **이 문서의 목적**
> 1. MTC 장비 환경에서 **카세트 단위 다중 QR 판독**을 앱의 QR 매칭 워크플로우에 통합하는 방식을 확정·기록한다.

> 3. 대화가 이어질 때마다 §2 확정 결정과 §9 미결을 갱신한다.
>
> **범위 밖**: 중앙 DB 취합(별도 문서, 보류). 리더기 자체의 광학·조명 튜닝(설비 담당).

## 1. 배경

### 1.1 작업 환경 (MTC)
- **MTC(Multi Chip Change)** 장비는 포트 단위 **카세트**로 구성되며, 카세트 1개 = **12 슬롯**. 각 슬롯에 **QR 칩 캐리어**가 마그네틱으로 부착되어 있고 캐리어 위에 팁이 얹혀 있다(팁과 캐리어는 함께 이동).
- MTC는 슬롯별로 캐리어를 픽업 → 프로브 핸드 부착 → 스윕 → 팁별 공진주파수 기준으로 결과(Frequency/Q)와 이미지를 저장한다. 이것이 앱이 파싱하는 **포트별 결과 폴더**(`summary_*.csv`, 12개)다.
- **불량 팁 분류 기능(최근 도입)**: MTC가 불량 팁을 **마지막 포트로 몰아넣는다.** 따라서 pass 포트에는 양품만 남는다.
- **결과 폴더의 슬롯 번호는 분류 이후의 최종 물리 위치를 기록한다** (2026-09-08 확정). → 캐리어 카세트를 그대로 찍으면 물리 위치 = 폴더 슬롯 번호.
- 다중 판독 최대 범위: **6 포트 × 12 슬롯 = 6 카세트 = 72 코드**를 한 화각에서.

### 1.2 현재 앱의 QR 경로
- `QRInputWidget`(`src/ui/widgets/qr_input_widget.py`): 입력창 Enter → `qr_scanned(str)` 1건.
- `QRMatchMixin._on_qr_scanned`(`src/ui/controllers/qr_match_mixin.py`): 선택 슬롯 1개에 매칭 후 다음 미매칭 슬롯으로 자동 이동. 로드된 세트 전체 QR 중복 검사.
- Pass Pool 경로 `PassPoolMixin._pool_on_qr_scanned`(`src/ui/controllers/pass_pool_mixin.py:261`): 선택 카드 1개에 매칭, **로드된 폴더 전체** 중복 검사, 원본 세트 자동 저장, 다음 미매칭 카드로 이동.
- 슬롯 코드 `_XXYY`: `parse_slot_code`(`src/core/slot_mapper.py`)가 `{atx, port, slot}` 을 돌려주고, 물리 배치는 3×4(하단 행 Slot 1~4, 상단 행 Slot 9~12).
- → 현재는 **"한 번에 한 코드"** 구조. 키보드(HID) 리더기로 72코드를 넣으면 포커스·순서·미판독 밀림 문제로 사용 불가.

### 1.3 현장 구성 (2026-09-08 사진 기준)
- 키엔스 **SR-X300W**(IP 192.168.100.2, TCP 9004, FW 1.73)를 암에 고정, 아래 **백라이트 투과 조명 스테이지**, 그 위에 캐리어 트레이(Boat No. 표기). 리더기 → 노트북 **LAN 케이블** 연결.
- **1차: 별도 지그** 형태로 구현. **향후: MTC 장비에 직접 부착.**

## 2. 확정 결정

| 결정 항목 | 채택안 | 핵심 이유 |
|---|---|---|
| **통신 방식** | **LAN(TCP/IP), 앱이 클라이언트로 리더기에 접속** | 포커스 무관·구조화 출력·앱이 트리거 시점과 대상 폴더를 통제. PC 인바운드 방화벽 불필요(리더기 IP만 허용). USB 가상 COM 은 동일 프로토콜이라 전송 계층만 교체 가능(QtSerialPort, 추가 의존성 0) |
| **입력 방식** | **데이터 출력(로그/스트림) 파싱** — 키보드 에뮬레이션 배제 | 72코드·미판독·순서 문제. 키보드 입력창은 단일 슬롯 정정용 폴백으로 유지 |
| **코드 ↔ 위치 대응** | **리더기 측 격자 번호 부여** (촬영 영역에 격자를 그려 셀 번호를 순서대로 부여) + **코드별 X,Y 좌표 부가 출력** | 리더기가 셀 번호를 직접 내주므로 앱은 좌표 분류기가 필요 없음. X,Y 는 캘리브레이션·이상 감지용 보조 정보 |
| **셀 번호 규약** | `cell = (port − 1) × 12 + slot` (1~72) 을 **리더기 격자 번호 순서로 그대로 채택** | 앱은 공식 하나로 (포트, 슬롯) 복원. 지그 → MTC 전환 시 **리더기 격자만 다시 그리면** 앱 무수정 |
| **슬롯 번호 기준** | 결과 폴더 = **최종 물리 위치** | 캐리어 카세트 물리 칸 = 폴더 슬롯 번호 → 대응 1겹 |
| **판독 단위** | 한 트리거로 화각 내 **전 카세트(최대 72)**, 로드된 폴더 탭 전체를 동시에 채움 | 포트는 슬롯 코드에 들어 있어 폴더 매칭이 자연스러움 |
| **적용 방식** | **검토 화면 확인 후 일괄 적용** (즉시 적용 금지) | 72칸 잘못 매칭의 되돌리기 비용이 큼 |
| **트리거** | **앱에서 명령 전송**(버튼/단축키) 기본, 리더기 버튼·외부 센서는 옵션 | 어느 판독이 어느 PO 세트에 속하는지 앱이 확정 |
| **Phase 2 셀 대응 (2026-09-09)** | 리더기 격자 번호를 그대로 `port = (cell−1)÷12+1`, `slot = (cell−1)%12+1` 로 해석. **카세트 1(셀 1~12) = Port 1**. MTC 물리 방향(하단 행 Slot 1~4)과의 대응은 F단계로 이관 | 현재 리더기 격자는 카세트당 3열×4행 래스터 순서이고 재번호가 가능하므로, 앱은 공식 하나로 고정하고 방향 차이는 리더기 격자 재정의로 흡수 |
| **출력 포맷 (2026-09-09)** | 현재 리더기 설정(고정 72개 + `ERROR` 자리표시, 서치 영역 번호·좌표 OFF)을 계약으로 확정. 셀 번호 = 리스트 인덱스 | 파서 단순화. 좌표는 필요 시 옵션으로 켜서 별도 캡처 후 추가 |

## 3. 리더기 출력 계약 (2026-09-09 확정, fixture `tests/fixtures/qr_reader/20260909_132804_full.raw`)

### 3.1 프레임

```
<code1>,<code2>,...,<code72>:<scantime>ms<CR>
예) 2680002971,268000296B,...,ERROR,ERROR,2680086CB6,...,2680086CBC:6064ms<CR>
```

| 항목 | 값 | 비고 |
|---|---|---|
| 헤더 / 푸터 | 없음 | 리더기 "출력 데이터 포맷 > 헤더" 비움 |
| 데이터 구분자 | `,` (0x2C) | 다중 바코드 판독 구분자 |
| 부가 데이터 구분자 | `:` (0x3A) | 뒤에 스캔타임 `NNNNms` (데이터 추가 > 스캔타임 ON) |
| 종단자 | `<CR>` (0x0D) 1개 | LF 없음 |
| 필드 수 | **72 고정** | 서치 영역 번호 1~72 순서. 개수 불일치 → 프레임 폐기 |
| 미판독 자리표시 | `ERROR` | 위치 유지 |
| 코드 길이 | 10자 영숫자 (예 `2680086CB6`) | 파서는 길이를 강제하지 않음 |
| 셀 번호 / X,Y | 출력 안 함 (인덱스로 대체) | 서치 영역 번호·코드 중심점 좌표 옵션 OFF |

### 3.2 명령·응답 (TCP 9004, 명령·데이터 동일 소켓)

| 항목 | 값 |
|---|---|
| 트리거 | **레벨 방식**. `LON<CR>` 판독 시작 → 전 코드 판독 전까지 결과 없음 → `LOFF<CR>` 에서 결과 프레임 확정 출력. 스캔타임 = LON→LOFF 간격 |
| 명령 응답 | `LON`/`LOFF` 는 무응답(결과만 출력). 그 외 `OK,<cmd>[,...]<CR>` / `ER,<cmd>,<code><CR>` |
| 연결 확인 | `KEYENCE<CR>` → `OK,KEYENCE,SR-X300,1.73,7.244<CR>` |
| 트리거 잠금 | `RLOCK<CR>` → `OK,RLOCK,UNLOCK<CR>` (LOCK 이면 판독 불가) |
| 오류 23 | AutoID Network Navigator 연결 중 → 외부 명령 전부 거부. 앱 사용 전 Navigator "연결 해제" 필수 (매뉴얼 10-2 p.59, 5-6 p.22, 오류 코드 표 p.100~101) |
| 종단자 수용 | 명령 CR / CR+LF / STX·ETX 모두 수용, 응답은 보낸 형식을 따름 |

### 3.3 리더기 설정 시트 (SR-X300W, 2026-09-09 현재)

| 항목 | 값 |
|---|---|
| Ethernet IP / 서브넷 | 192.168.100.2 / 24 (노트북 192.168.100.1) |
| 이더넷 데이터(서버) | TCP 9004, Keep Alive 사용 |
| 출력 데이터 포맷 | 헤더 없음, 터미네이터 `0D`, 부가 데이터 구분자 `3A`, 데이터간 구분자 `2C` |
| 데이터 추가 | 스캔타임 ON. 코드 중심점 좌표·서치 영역 번호·심볼·시간 OFF |
| 다중 코드 판독 | 서치 영역 72개(카세트 6 × 3열×4행), 고정 개수, 미판독 `ERROR` 출력 |
| 조명 | 편광, 노출 5922µs, 게인 22, HDR (뱅크 1) — 셀 13·14 미판독 재현됨(E단계 조명 튜닝 항목) |

## 4. 앱 아키텍처

```
리더기 (TCP 서버)  ◄── 트리거 명령 ──  src/core/qr_reader/keyence_client.py  (QTcpSocket, 메인 스레드 시그널)
                   ── 결과 프레임 ──►        │ frame_received(str)
                                             ▼
                                   payload_parser.py  (순수 함수) → list[CellRead(cell, code|None, x, y)]
                                             ▼
                                   slot_assigner.py   (순수 함수) → cell → (port, slot) → 로드된 폴더의 SlotData
                                             ▼
                              QRMatchMixin._on_batch_read(...)  → 검토 다이얼로그 → 일괄 적용(기존 매칭·중복·저장 로직 재사용)
```

- **`src/core/qr_reader/`** 신규 패키지
  - `payload_parser.py`: 프레임 문자열 → `CellRead` 목록. 하드웨어 없이 fixture 로 테스트.
  - `slot_assigner.py`: `cell → (port, slot)` 공식 + 선택적 **override 표**(특수 배치용). 로드된 `MeasurementSet` 들에서 슬롯 코드로 대상 `SlotData` 탐색, 분류 결과 `AssignPlan`(적용 가능 / NG / 중복 / 기존 QR 충돌 / 레코드 없음).
  - `keyence_client.py`: `QTcpSocket` 접속·재접속·종단자 프레이밍·트리거 명령·타임아웃. 스레드 없이 시그널로 결과 전달(OCR/업로드 워커와 동일한 "DB 는 메인 스레드" 규칙).
  - `settings.py`: `app_settings.qr_reader` 키 — `{transport: lan|serial|keyboard, host, data_port, cmd_port, trigger_cmd, ng_token, separators…, cell_override: {cell: [port, slot]}}`.
- **컨트롤러**: `QRMatchMixin` 에 `_on_batch_read(reads)` 추가. 적용 시 슬롯별로 기존 `_match_qr_atx` / `_pool_on_qr_scanned` 의 중복 검사·자동 저장 의미를 그대로 유지(ATX 탭·Pass Pool 양쪽에서 호출 가능).
- **UI** (목업 승인 2026-09-09: [Keyence Cassette Scan UI](https://claude.ai/code/artifact/868c790f-eef6-4937-ae54-5cbbb723f208))
  - **메인 창 하단 바**: 기존 QR 입력 오른쪽에 리더기 상태 칩(● Reader 192.168.100.2 SR-X300W, 클릭 시 설정) + **"카세트 스캔"** 버튼(F9). 진행률 바는 유지.
  - **검토 다이얼로그 "카세트 판독 검토"**: 상단 요약 칩(판독 n/72 · 적용 가능 · NG · 동일 · 중복 · 충돌 · 레코드 없음 · 제외) + "이상 칸만 보기" + 범례. 본문은 리더기 격자 순서대로 Port 1~6 패널(각 3열×4행, 셀 번호·S번호·코드·상태 배지). 폴더 미로드 포트는 "자동 제외"로 흐리게. 하단에 차단 사유와 [재판독][취소][적용 (n)]. 레코드 없음이 1칸이라도 있으면 적용 비활성, 충돌·중복 칸은 적용에서 제외(덮어쓰기는 칸 우클릭).
  - **리더기 설정 다이얼로그**: 연결(전송 방식 LAN/Serial/Keyboard, IP, 포트, 자동 재접속) · 판독(LON/LOFF, 판독 시간 s, 기대 코드 수, NG 문자열) · 셀→Port/Slot(공식 / 재정의 표) · 하단 상태(연결됨 · 모델 · FW) + [연결 테스트][테스트 판독][취소][저장].
- **폴백**: 기존 키보드 입력창 유지(단일 정정, 리더기 장애).

## 5. 예외 처리 규칙

| 상황 | 처리 |
|---|---|
| NG(미판독) 셀 | 빈 슬롯 유지, 검토 화면에 표시. 적용 후 키보드 스캔으로 개별 보완 |
| 레코드 있음 + 코드 없음 | 경고(캐리어 이탈/미판독). 적용은 허용(해당 칸만 미매칭) |
| 레코드 없음 + 코드 있음 | **적용 차단** — MTC 결과와 실물 불일치 신호(불량 포트 캐리어·폴더 미로드) |
| 로드된 폴더 전체에서 QR 중복 | 해당 칸 적용 차단 + 중복 위치 표시(기존 규칙) |
| 기존 QR 있는 슬롯에 다른 코드 | 적용 차단(기존 규칙 "이미 QR 있음"). 덮어쓰기는 검토 화면에서 명시적 선택 시에만 |
| 불량(마지막) 포트 카세트가 화각에 포함 | 해당 폴더 미로드 또는 pass 슬롯 0건이면 자동 제외 |
| 프레임 잘림·개수 불일치 | 프레임 폐기 + 재트리거 안내. 로그에 판독 시각·코드 수 기록 |
| 리더기 연결 끊김 | 상태 표시 갱신, 자동 재접속(백오프), 스캔 버튼 비활성 |
